## Phase 3: Multi-Agent Adapters, Postmortem & Spec Alignment

Scope: Rename the package to `silverquillm`, refactor config to match the spec's nested schema, introduce an adapter abstraction for multi-agent support, add postmortem logging and setup-question validation, fix known bugs, and sync repo documentation.

---

- [x] **Rename ****`benchmark/`**** package to ****`silverquillm/`** — Rename the directory, update all `from benchmark.*` imports (source + tests + CLI entry points), update `pyproject.toml` package discovery and `[project.scripts]`, verify clean install.
- [x] **Refactor ****`BenchmarkConfig`**** to use nested ****`agent:`**** block** — Create `AgentConfig` dataclass with `adapter`, `max_test_rounds`, `timeout_per_card`, `disable_web_search`. Embed as `agent: AgentConfig` in `BenchmarkConfig`. Update `load_config()` for nested YAML. Update `config.example.yaml`.
- [x] **Update all ****`BenchmarkConfig`**** consumers for nested agent config** — Audit every module reading `config.agent_tool`, `config.max_test_rounds`, `config.timeout_per_card`, `config.disable_web_search` and migrate to `config.agent.*`. Update tests.
- [x] **Create ****`AgentAdapter`**** abstract base class** — Define `silverquillm/adapters/base.py` with abstract `run(prompt, workspace) -> str`, `setup()`, `teardown()`. Include timeout/retry logic and factory `get_adapter(config) -> AgentAdapter`.
- [x] **Implement ****`OpenCodeAdapter`** — Create `silverquillm/adapters/opencode.py`. Remove invalid `--thinking` flag. Pass prompts via stdin or temp file (not CLI arg). Wire into adapter factory.
- [x] **Implement ****`ClaudeCodeAdapter`** — Create `silverquillm/adapters/claude_code.py` wrapping the `claude` CLI. Handle prompt via stdin/temp file. Wire into factory.
- [x] **Implement ****`AiderAdapter`** — Create `silverquillm/adapters/aider.py` wrapping the `aider` CLI. Wire into factory.
- [x] **Implement ****`PiAdapter`** — Create `silverquillm/adapters/pi.py` wrapping the `pi` CLI. Wire into factory.
- [x] **Refactor ****`agent_session.py`**** to use ****`AgentAdapter`** — Replace hardcoded `_run_opencode()` with adapter resolved from `config.agent.adapter`. Remove all OpenCode-specific logic from session; it should be adapter-agnostic.
- [x] **Implement postmortem JSONL logging** — After each agent invocation per card, append structured JSON to `<output_dir>/<card>/postmortem.jsonl` (prompt, response, tokens, timing, round, status).
- [x] **Implement ****`agent_thoughts.md`**** narrative generation** — After all rounds for a card, generate `<output_dir>/<card>/agent_thoughts.md` summarizing reasoning across rounds.
- [x] **Implement setup questions validation** — Create `silverquillm/setup_questions.py`: load `setup_questions.json`, send each to adapter, check answers, abort if validation fails.
- [ ] **Create ****`setup_questions.json`**** question bank** — Author initial questions verifying agent understands engine API, test conventions, and workspace layout.
- [ ] **Audit and align tier key naming (****`tier`**** vs ****`complexity_tier`****)** — Standardize on one key across classifier, scorer, evaluator, and card specs. Add round-trip test.
- [ ] **Fix prompt templates: add explicit output filenames** — In `prompts.py`, update `_BLIND_IMPLEMENTATION_TEMPLATE` to include `Write your implementation to blind_impl.py`. Update `_TEST_INFORMED_TEMPLATE` to include `Save your updated implementation to tested_impl.py. Save your tests to tests.py.` Update `_ITERATION_FEEDBACK_TEMPLATE` to say `resubmit tested_impl.py and tests.py`. Without these, agents don't know where to write files.
- [ ] **Implement persistent engine per run** — Refactor `agent_session.py` workspace setup: instead of copying `engine/` read-only per card, create a persistent run-level engine directory at run start. Each card's workspace gets a writable copy (or symlink) of the run engine. After each card completes, commit engine changes back to the run-level directory. Remove `engine/` from `_PROTECTED_DIRS`. Remove read-only chmod on engine files. Save final engine state as a run artifact.
- [ ] **Implement regression test runner** — After each card's test-informed phase completes, re-run all previously-completed cards' tests against the current persistent engine + their implementations. Record per-card regression results (which earlier cards broke, which tests failed). Feed regression failures back to the agent as an additional correction round if rounds remain. Store regression results in `result.json` per card.
- [ ] **Sort cards by complexity tier for sequential processing** — In the orchestration loop (`cli.py`), sort cards by complexity tier (trivial → expert) before processing. Within a tier, sort by collector number for determinism. This ensures the agent builds up engine capabilities gradually.
- [ ] **Capture engine diffs as per-card artifacts** — After each card completes, compute a diff of engine changes made during that card's session. Save as `engine_diff.patch` in the card's results directory. Also save cumulative engine state snapshot at run end.
- [ ] **Update prompts to inform agents about engine extensibility** — Update blind and test-informed prompt templates to tell agents: (1) `engine/` is writable and they may extend it, (2) all previous cards' tests will be re-run after each card, (3) engine changes must not break existing functionality. See updated prompts in [BENCHMARK-RUNNER.md](http://benchmark-runner.md/) spec.
- [ ] **Add Category 4 scoring: Engine Extension Quality** — In `scorer.py`, add metrics for regression rate, regression-free streak, engine churn (lines changed in engine/), and mechanic reuse rate. Update `generate_leaderboard` to include Category 4 table. Update `save_aggregates` to include Category 4 data.
- [ ] **Expand Foundations card pool (batch 1: +30 cards)** — Port ~30 additional Foundations cards prioritizing untested engine mechanics (enchantments, planeswalkers, modal spells). Include unit tests. *(Lower priority, can be split further.)*
