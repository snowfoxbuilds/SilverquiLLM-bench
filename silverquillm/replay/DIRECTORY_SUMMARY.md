# Directory Summary — `silverquillm/replay/`

## Overview

- **Responsibility**: 17lands GRE replay data parser, executor, and validation pipeline. Parses pre-parsed GRE message streams from 17lands replay exports into structured game objects, then validates the SilverquiLLM engine's behavior against real Arena game state snapshots.
- **The "Why"**: Provides ground-truth validation by replaying actual MTG Arena games through the engine and detecting where engine behavior diverges from the official game client.
- **Dependencies**:
  - Upstream: `engine/` (game engine for replay execution), `data/replays/` (card ID map, sample replays)
  - Downstream: `silverquillm/cli.py` (registers `validate` subcommand)

## Architecture & Patterns

- **Pipeline**: Raw JSON → `parse_replay()` → `ReplayGame` → `ReplayExecutor`/`ValidatingExecutor` → `ValidationReport`
- **Registry is what makes validation real**: with no registry every card is a generic `CardImpl` placeholder and *nothing diverges*. `cli.py` resolves a workspace (`--workspace`, or `--benchmark <id>` → `benchmarks/<id>/workspace`), imports that workspace's own `cards.loader` to build the registry (the workspace owns its card pool — its tests and agent harnesses build the same registry), and passes it to `ReplayExecutor`. For hob-medium the card set is `fdn` (replays are FDN-format). SOS gets no registry, preserving its frozen scripted-player path.
- **Caveat — swallowed failures (observer mode)**: when a registered card's ability resolution raises in observer mode, the executor logs `Ability engine resolution failed …` and applies a snapshot/life-delta fallback rather than recording a divergence, so impl bugs (e.g. a `NameError` in a trigger) appear only in logs, not in the report's divergence count. Simulate mode records these as `ENGINE_ERROR` divergences instead.
- **State reconstruction**: GRE messages come as Full or Diff; `apply_full_state()` builds complete snapshots, `apply_diff()` merges sparse updates into previous state.
- **Two execution modes**: default **observer mode** (state mirroring with pre-compare sync — the frozen SOS behavior) and **simulate mode** (`--simulate`, hob-medium): gameplay is driven through the engine — `cast_spell` with GRE-derived target Intents and ManaPaid-funded mana (pool credited by look-ahead, taps land at the annotation's home snapshot), `play_land`, flashback-style casts via `cast_spell_free` from graveyard/exile (the graveyard→stack path passes an explicit `mode=CastMode.FLASHBACK` when the GRE transition and the card's own flashback cost attest it — engines without cast modes are called without one; the engine never infers the mode, and the hob-medium engine then exiles that cast at any stack exit, resolution or countering), activated abilities via `activate_ability` (a single-ability source is driven directly; a **multi-ability** source is driven only when exactly one ability's pure `predicted_outcome(game, source)` matches the observed prev→curr GRE delta — `_disambiguate_multi_ability` — and otherwise falls through, recording the source in `_ambiguous_sources` so its mismatches are floor-tagged `ambiguous-ability`), engine combat from `attackState`/`blockState` walking the GRE damage-step sequence (separate first-strike/normal passes), multi-blocker damage order answered from observed deaths, turn-structure events (upkeep/begin-combat/end-step) fired at GRE step boundaries plus a replay-side cleanup at the turn boundary, mulligan-aware draws through the engine library — then, just before comparison, engine-minted tokens are correlated to their GRE grpId (Phase E token identity map + signature/colour/copy-name matching) and counter state is synced from the GRE `CounterAdded`/`CounterRemoved` stream — a ledger keyed by the engine-object key **`(object_id, id(obj))`** (which survives GRE instance-id churn; `object_id` alone is not unique — a copy-token impl `copy.copy`s the copied card, so a token copy shares its original's `object_id` — and every keyed structure pins its objects so a key is never reused while referenced) reconciled as an authoritative SET onto the correlated permanent (`_apply_counter_annotations`), so a counter whose source trigger the executor never fired still lands (+1/+1 restores P/T; named counters like Drake Hatcher's incubation go to `_generic_counters`) without double-counting an engine-driven counter (the SET caps the engine's own trigger-driven counters at the GRE total). A counter never crosses a real zone-change boundary — the battlefield STINT is (engine-object key, fold-time `refs.zone_epoch`): a ledger retires when its object LEAVES the engine battlefield (blink/bounce/death/reanimation; membership read directly from the engine zones) OR when its zone epoch advanced (`refs.zone_epoch(obj)` is a pure-read monotonic per-object zone-change count bumped by `move_to_zone` via `note_zone_change`), which catches a leave-and-return completed entirely within one replay step — an atomic blink — that end-of-step membership cannot see. Neither signal calls `refs.instance_id` (which would mint stint ids as a side effect). Retirement clears the stale counters (and `_base_*` shadows) (`_retire_departed_counters`). The SET is applied only when the ledger changed this snapshot (a fold); it persists via the `_base_*` shadow, so it is not re-forced every snapshot (which fought the oracle P/T resync at timing windows). An annotation whose affected id is not yet correlated is deferred and retried under stint-safe rules — a fold requires GRE to attest the affected id ON the battlefield in the CURRENT snapshot with an identity (grpId/owner) consistent with the effect's recorded context, and an engine candidate on the engine battlefield with no grpId/controller/owner contradiction (`_engine_candidate_valid`; same-snapshot new-permanent matching in `_match_new_battlefield_permanent` requires GRE battlefield residency and filters by controller seat, so a graveyard twin or another player's same-grpId permanent never matches). One semantic counter effect keeps ONE identity across GRE instance-id changes: every `ObjectIdChanged` link is accumulated game-wide (`_counter_aid_alias`) and all effect state (pending/applied/cancelled) is keyed by the CANONICAL (annotation id, rename-chain-root aid) — a persistent-slot repeat under any renamed aid resolves to the same record, so it can never mint a second effect, double-apply a folded one, or resurrect a cancelled one (distinct affected ids of a multi-affected annotation have distinct roots and stay independent). A pending effect CONTINUES across an id change only on positive engine proof of same-stint churn: a single `ObjectIdChanged` hop to a battlefield-resident, identity-consistent target AND an anchored engine candidate (first resolved-and-validated correlation, pinned in the payload, with its capture pass stamped) that is on the engine battlefield right now with epoch evidence obeying the same window-start rule as folds (below) — GRE-side consistency alone cannot distinguish churn from a direct/compressed leave-and-return, so anything less (no anchor, anchor departed, anchor absent from the window-start census, epoch advanced, a rename CHAIN — always a zone transit) cancels instead of speculating. Folds bracket the COMPLETE relevant GRE battlefield window: the first reconciliation pass on which GRE attests the effect's identity on the battlefield opens the window (`battlefield_since`, stamped alongside `pending_since`; for an effect first observed off the battlefield the window begins on arrival) and freezes the engine battlefield CENSUS of that pass (`window_epochs`: counter key → zone epoch); a fold requires the resolved candidate to appear in that frozen census with its CURRENT epoch equal to the census value — proving it was on the engine battlefield at the window start and underwent no zone transition since. On the window-start pass itself any validated candidate satisfies this trivially (zero-width window — same-snapshot creation/token correlation, and an off-battlefield-observed effect whose GRE object and engine candidate arrive together, fold immediately), and a window-start resident that is merely uncorrelated still folds when correlation arrives with its epoch unchanged. A candidate ABSENT from the census (created, resync-injected, returned, or renamed-in after the window began) is unproven FOREVER — waiting extra passes never converts an after-boundary first observation into valid evidence ("candidate not on the engine battlefield at the start of the GRE battlefield window; same-stint continuity unproven") — and an epoch advanced past the census value cancels ("engine zone epoch advanced during the GRE battlefield window"), so an old pending effect can never land on a returned stint, whether GRE kept the aid, renamed it once, or renamed it through a chain; a candidate contradicting the anchor cancels likewise. (`bf_epochs` still records every battlefield object's `(zone epoch, reconciliation pass)` at its earliest pendency observation — pre-window churn evidence and key pinning.) An effect EXPIRES — cancelled, recorded in `_unresolved_counter_effects` (with its canonical and current aid, its `pending_since`/`battlefield_since`/`anchor_pass` stamps, and a reason), never applied late — when its GRE stint disappears or leaves the battlefield before correlation. Token correlation publishes the GRE-instance→engine-object binding (`_counter_token_binding`) counter sync needs. Then — **Phase N (issue #56)** — the compared P/T is re-derived once (`_rederive_pt_pre_compare` → `_safe_apply_all`) BEFORE comparison, but only when driving this step registered or removed a real (non-oracle) continuous effect (`_nonoracle_effect_ids()` changed across the step), so a triggered-ability buff that resolved this step (e.g. Dauntless Veteran's attack-trigger "+1/+1 until end of turn") lands in the compared value at compare time instead of one comparison boundary late in the resync — the triggered-ability P/T analogue of Phase G's arrival-aligned spell resolution. The oracle base is preserved (the pass never clears `_ORACLE_PT_SOURCE`; `apply_all` re-applies base + this-step's real effects); the gate skips no-effect steps (idempotent with the resync, keeps the fast path) and steps where the effect layer already crashed (`_effects_broken`). The gate keying on effect registration is also what keeps dynamic-P/T `hidden-information` cards (Consuming Aberration's library-driven `*/*`, a static ability registered once at ETB) from being re-derived against the eager engine graveyard — no card special-case needed. Then state is compared BEFORE an oracle resync, so each step validates independently. The resync corrects any remaining P/T through revocable, replay-owned ContinuousEffects (Layer 7/7c, sentinel source `_ORACLE_PT_SOURCE`), cleared and re-derived per step — printed/modified stats are never written directly. Counter sync and token correlation are simulate-only (observer mode never calls them; observer output stays byte-identical). **Phase O (issue #57)**: the same correlation pass also credits token PRODUCIBILITY independently of co-presence — `_correlate_tokens_in_group` records into `_impl_minted_token_grpids` every is_token engine object whose identity resolves UNIQUELY (`_engine_token_impl_identity`, reusing the exact stamping evidence — globally-unique signature, or `_resolve_colliding_identity`'s colour+copy-name discrimination — minus the GRE-presence requirement), so a token the engine mints a snapshot before GRE attests it (then the overflow pass removes it, so the two never co-occur to correlate) is still proven producible. The corpus's dominant unminted-token cause is this mint-cadence offset, not a missing minter: the impls mint the tokens with correct characteristics, so the residual is a `resolution-cadence` zone offset and the false `MISSING_CARD` is suppressed.
- **Dirty-state / recovery invariant (simulate mode)**: a transition is measurable only when it starts from fully restored GRE truth, across **two independent synchronization domains** — the compared surfaces / P/T (`_synced`, owned by `_resync_to_snapshot`) **and** operational untap state (`_operational_dirty`, owned by the turn-boundary untap). The executor is fully synchronized (`_fully_synced`) only when both are clean; a successful P/T resync sets `_synced` but never touches `_operational_dirty`, so restoring one domain can never speak for the other. `_resync_to_snapshot` returns whether it fully restored the compared surfaces; its card-code surfaces are guarded so the compared state is still reconciled where possible (trigger registration on injected permanents is guarded per card and never aborts the sync — only `apply_all`, the effect re-derivation, can leave a compared value — P/T — dirty, in which case `_effects_broken` latches so it is never re-run). `execute_step` checks `_fully_synced` before touching turn structure: on a compared-domain-dirty entry it recovers to the previous snapshot; operational dirtiness has no mid-turn reconstruction point so it forces suppression outright. If recovery can't complete the transition is **unmeasurable** — no comparison is emitted from dirty state; a `REPLAY_INFRA` "unmeasurable transition" is recorded and the engine is resynced forward so a later step can self-heal. Turn-boundary cleanup and untap are guarded independently, so a cleanup (effect) crash never skips the untap; a non-protocol **untap** crash records the `ENGINE_ERROR` and is repaired by a deterministic, idempotent fallback (`_fallback_untap` — untap permanents, clear summoning sickness, reset land plays — never a retry of the failing `untap_step`), keeping the following transition measurable. Only if even the fallback cannot complete does `_operational_dirty` latch, suppressing every later transition (the fail-closed floor — a suppressed step returns before `_handle_turn_info`, so no later untap runs to clear it). A **protocol** untap failure (`ProtocolError`/`UnmatchedQueryError`) obeys the same barrier: it is re-raised for classification only AFTER the repair-or-latch runs — it records no `ENGINE_ERROR` (protocol classification is never converted), and `_fallback_untap` latches `_operational_dirty` before it re-raises a protocol exception mid-repair, so a recorded `PROTOCOL_ERROR`/`QUERY_UNANSWERED` can never leave the operational domain silently dirty for the post-exception P/T resync to paper over. Any secondary exception the fallback raises is contained so the *primary* untap exception keeps its classification.
- **Dual-seat model**: Seat 1 (17lands user) is fully validated against engine; Seat 2 (opponent) actions are injected as oracle data (observer mode) or run through the engine once GRE reveals them (simulate mode). Hidden-origin plays (opponent casts/land plays, whose pre-move object never appears in the prior snapshot) are synthesized from the arrival side by `_infer_hidden_origin_actions`.
- **Divergence types**: `MISSING_CARD` (card not in engine registry — in simulate mode one divergence per (game, identity), covering parser actions, executor-synthesized hidden-origin actions, and unmapped/unregistered battlefield arrivals; observer mode keeps per-occurrence counting over parser actions only; **a deferred token MISSING is suppressed when the token is producible — `_minted_token_grpids` (minted AND correlated) OR Phase O's `_impl_minted_token_grpids` (a real impl minted a uniquely-identifiable token, even if a mint-cadence offset kept it from ever correlating), so "no engine impl that mints it" is never a false positive for a token the engine actually mints**), `STATE_MISMATCH` (engine state differs from GRE), `ILLEGAL_ACTION` (engine rejects valid Arena action), `ENGINE_ERROR` (engine raises exception / API fallback in simulate mode; card crashes are per-action records, never step aborts), `QUERY_UNANSWERED` / `PROTOCOL_ERROR` (V2 Player Query protocol failures), `REPLAY_INFRA` (simulate mode: executor-side impossibility — library empty on a GRE draw, step-event plumbing — or a transition suppressed as unmeasurable because a prior step left a synchronization domain dirty and recovery could not restore GRE truth: either the compared/P/T surfaces (a resync that could not complete) or operational untap state (an unrecoverable untap latched via `_operational_dirty`); kept out of the engine/card-bug signal).
- **Limitation attribution (simulate mode, Phase M)**: every recorded divergence is mapped to exactly one named limitation class by `limitations.classify_limitation` at report serialization (`cli._divergence_record`, simulate-gated so observer stays byte-identical). Three *floor* tags name genuine stream limitations the corpus cannot overcome — `unfunded-activation` (no attested ManaPaid/manaPool/counter covers the cost), `ambiguous-ability` (a multi-ability source the stream under-determines, from `ValidationReport.ambiguous_sources`), `hidden-information` (value depends on a zone GRE does not attest — grpId-0 shells, a library-driven P/T, out-of-set tokens). Four *family* tags name fixable engine/card gaps (future work) — `unimplemented-effect`, `resolution-cadence`, `driving-context`, `replay-infra`. The taxonomy is TOTAL (no untagged survivor); `scripts/triage_divergences.py` reconciles it (`_limitation_reconciliation`, exit 4 on any untagged/unknown tag), and each floor tag is proven on a golden by `engine_tests/test_replay_limitations.py::TestLimitationEvidence`. **Phase O (issue #57)** threads `ValidationReport.impl_minted_token_grpids` per-game into `LimitationContext`, so a snapshot-extra token the game's impls mint is re-attributed from `unimplemented-effect` to `resolution-cadence` (a mint-cadence offset the engine does produce), and the correlation-refused 1/1 black Rat 94169 (`CORRELATION_REFUSED_TOKENS`) is floored `hidden-information` — proven by the co-presence measurement (it is the only token id-less on the engine battlefield the same snapshot GRE attests it yet never stamped, because the same-colour Burglar Rat copy 93883 shares its signature).
- **Diff semantics**: GRE diffs re-send **complete** objects with protobuf default-omission — `apply_diff` replaces gameObjects (a re-sent permanent without `isTapped` is untapped).
- **ObjectTracker**: Tracks GRE `objectId` changes across zone transitions via `ObjectIdChanged` annotations.

## Developer Guide & Constraints

- **Entry Points**: Start with `parser.py` → `parse_replay()` for understanding the data flow, then `executor.py` → `ReplayExecutor` for engine integration.
- **Extension**: Add new action types in `state.py` → `infer_actions()`. Add new divergence checks in `validation.py` → `ValidatingExecutor`.
- **Constraints**:
  - Card ID map (`data/replays/card_id_map.json`) must be kept in sync when new cards are added; use `scripts/build_card_id_map.py` to regenerate.
  - `GameSnapshot` objects are immutable once created — state reconstruction creates new copies.
  - `ReplayExecutor` expects snapshots in chronological order.
