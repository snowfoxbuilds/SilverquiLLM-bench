# Directory Summary — `docs/`

## Purpose

Documentation and specification files for the SilverquiLLM-bench project. Contains design specs synced from Notion, plus auto-generated reference docs for agents.

## Key Files

| Path | Responsibility |
|------|---------------|
| `specs/PROJECT-OVERVIEW.md` | High-level project description and goals |
| `specs/GAME-ENGINE.md` | Game engine architecture and rules coverage spec |
| `specs/CARD-INTERFACE.md` | Card implementation interface and hook method spec |
| `specs/BENCHMARK-RUNNER.md` | Benchmark runner design for LLM evaluation |
| `specs/SCORING.md` | Scoring criteria and evaluation methodology |
| `specs/TEST-SUITE.md` | Test suite design and coverage requirements |
| `engine_api.md` | **Auto-generated** engine API reference (~5,000 tokens) — produced by `benchmark/docs_gen.py` via AST extraction. Used as agent context. |
| `test_utils.md` | **API reference** for test helpers: `create_game`, `set_board_state`, `cast_spell`, `advance_to_phase`, `declare_attackers`, `declare_blockers`. |
| `TODO_COMPLETED.md` | Record of completed TODO items. |

## Dependencies

- Specs are synced from Notion using the root-level `sync_notion_specs.py` script.
- `engine_api.md` is regenerated by running `benchmark/docs_gen.py`; it reads `engine/` source via AST.
- `test_utils.md` documents the test helper API in `tests/test_utils.py`.

## Notes

- Specs in `specs/` are reference documents, not executable code.
- `engine_api.md` and `test_utils.md` are meant to be included in LLM agent context windows during benchmark runs.
- The specs directory is populated by the `sync_notion_specs.py` tool and may be updated independently of the codebase.
