# Directory Summary — `scripts/`

## Purpose

Standalone utility scripts for data pipeline tasks. Not part of the main package — run directly via `python scripts/<script>.py`.

## Key Files

| File | Lines | Responsibility |
|------|-------|---------------|
| `build_card_id_map.py` | 230 | Fetches card data from Scryfall API and builds `data/replays/card_id_map.json`. Creates `grpId_to_card_name` forward map and `card_name_to_grpIds` reverse map (list-valued for duplicate-name disambiguation). Adds synthetic entries for SPG #74–83 (grpIds 94700–94709) flagged with `"synthetic": true`. Includes error handling for curl/Scryfall API failures. |
| `generate_audited_stubs.py` | ~200 | Reads `benchmarks/sos/data/sos.json` and generates `cards/stubs/sos_stubs.py` containing one stub class per card with colors, hybrid mana, planeswalker loyalty, Vehicle P/T, and `register_sos_stubs(registry)`. |
| `harvest_validated_results.py` | ~530 | **Phase 19 harvest pipeline — discovery, row emission, and summary analysis.** Discovers validated results by globbing `docker/*/validated_results/*/`. Exposes `discover_validated_runs(repo_root, *, image, run, card) -> list[ValidatedRun]` (sorted, filtered), `build_rows_for_run(vr, *, harvested_at) -> list[dict]` (one dict per `(card, test_node)` with keys `image, run, card, test_node, outcome, tests_hash, passed, failed, total, complexity_tier, harvested_at`), and `harvest(repo_root, *, bench, output, image, run, card, harvested_at, results_repo) -> int` (full pipeline: discover → build rows → truncate-write JSONL → return row count). **`--results-repo <clone>`** (or `$SILVERQUILLM_RESULTS_REPO`) switches discovery to the migrated private results repo: `_discover_from_results_repo` follows each record's `legacy-tree` artifact pointer back into the legacy tree for per-card content, rechecking right before the pointer is followed that it equals the canonical identity-bound path (`legacy_tree_location`) — a mismatch raises rather than emitting rows under another candidate's label; the `image` column carries the legacy identity, and the rows are identical to the in-repo walk's (`tests/test_harvest_results_repo.py`). The in-repo walk stays the default. `main()` supports two modes: default harvest mode (delegates to `harvest()`) and **`--summary` mode** (delegates to `summarize_breadth(rows)`). **`--summary` mode** reusable API: `load_rows(path) -> list[dict]` reads a JSONL harvest file; `summarize_breadth(rows) -> list[dict]` groups rows by `(card, test_node, tests_hash)`, counts distinct failing images (cross-impl breadth), and returns records sorted descending by breadth; `write_summary(summary, path)` writes the result to `benchmarks/<bench>/analysis/harvested_summary.json`. Creates `benchmarks/<bench>/analysis/` on first run. **Legacy branch**: cards whose `result.json` lacks the `test_nodes` key (pre-items-1/2 results) are handled separately — `_extract_fail_nodes_from_errors(errors)` parses `FAILED`/`ERROR` lines from `result_data["errors"]` into normalized pytest node IDs; `build_rows_for_run` emits one `outcome="fail"` row per unique fail node plus one `outcome="rollup"` row for `test_node="__rollup__"` carrying pass/fail/total counts; `tests_hash` is `None` for all legacy rows. `harvest()` prints a one-per-run `[legacy] <image>/<run>` notice for any run that produced `__rollup__` rows. |
| `migrate_validated_results.py` | ~330 | **Legacy → results-repo backfill (#63 Part B).** Walks `docker/*/validated_results/*/` and writes one immutable Run Record per run into the private results repo via `silverquillm.results_repo`: `legacy` identity (`legacy:<image-dir>`), `mode: "legacy"` uniformly, `benchmark` from the manifest's `benchmark_set` (fallback `sos`), the older `cards` manifest key accepted beside `card_filter`, `leaderboard_valid` from `derive_leaderboard_valid` with a `validity_note` in `run_metadata` when false, scores mapped to the neutral keys, and one `legacy-tree` artifact pointer at the run dir. Exposes `discover_legacy_runs`, `build_legacy_record` (raises `LegacyRunUnparseable` — runs lacking `run_manifest.json`/`run_summary.json`/`eval_result.json`, and image/run dir names that are not safe path segments, are listed loudly and skipped, never guessed or sanitized), `plan_migration`, `apply_migration`, `format_plan`, `main(argv, repo_root=)`. The `legacy-tree` pointer comes from `legacy_tree_location`, the same canonical helper the record validator and the harvester check against. `--dry-run` prints the full plan; re-runs skip destinations whose existing record is byte-identical and abort with a `CONFLICTS` listing (exit 1, nothing written, index untouched, no traceback) when any destination holds an unreadable, malformed, incomplete, or differing record; the source tree is never modified and conflicting records are never overwritten. Real-corpus expectations (82 runs → 79 records, 3 `workspace_final`-only skips, 77 valid / 2 invalid) are pinned in `tests/test_migrate_validated_results.py`. |
| `promote_candidate.py` | **Promote gate (#39 §4 / #66 Part A).** `promote(config_repo, worker_type, candidates_dir=, slug=, docker_config=, resolve_digest=, now=, dry_run=)` copies one worker-type definition from a Config Repo into `candidates/<slug>--<hash8>/`: exports the bundle with TheOzolith's `export_candidate` into a private staging dir beside the destination, ingests it through `silverquillm.candidate.load_candidate_bundle` (identity recomputed, secret values refused), names the directory by the recomputed hash8, vendors the definition (top-level `base` pinned to the resolved digest when the source carried the tag only — `pin_base_in_definition`) and the referenced knowledge and policy source trees (regular files only; symlinks and unreadable files refuse), dedups by identity **and source** (a symlink under a candidate name in `candidates/` is `PromotionRefused`, never followed; same identity under this name = no-op only when the existing bundle verifies, the existing `source/` re-exports to it byte for byte and equals the staged source byte for byte — the README is never compared; a tampered / missing / differing source, a bundle that does not recompute to its name, or the same identity under another slug = `PromotionRefused`, existing directory untouched), proves re-export from `source/` reproduces `bundle/` byte for byte, writes a README stub with `TODO(promote)` placeholders and no host-local path (`refuse_host_paths`: generated files may name neither the Config Repo path, the home directory nor the Docker config dir), scans the **complete** staged tree with the production credential detector (`refuse_credentials` → `scan_tree_for_credentials`: bundle, definition, knowledge source incl. `PUBLISHABLE`, policy source, README; a declared slot assigned any non-empty value — no length or charset rule — is a hit, an empty assignment or a bare mention is not; a hit names file and shape only), and publishes with one rename. **Vendor-at-promote is strict** (`check_knowledge_publishable`): a referenced knowledge tree must exist and carry a `PUBLISHABLE` marker file at its root, else a hard refusal naming the rule (knowledge that cannot be published ⇒ the candidate cannot be promoted ⇒ its results cannot be published). Idempotent, side-effect-free on refusal, never runs git. CLI: `<config-repo> <worker-type> [--slug] [--candidates-dir] [--docker-config] [--dry-run]`; exit 1 on `REFUSED`. |
| `publish_results.py` | **Publish gate (#39 §4 / #66 Part A).** `plan_publication(run_ids, results_repo=, dest=, candidates_dir=, allow_invalid=)` checks every named run before anything is written: `find_run_record` / `source_record_dir` (the one `results/<hash>/<run-id>/`, re-proven on read and proven a real in-tree record through every ancestor: `results/`, the candidate-hash directory and the run directory real directories, `manifest.json`/`scores.json` regular files by `lstat` — `_require_real_directory` / `_require_regular_file`; a symlink at any component refuses, never followed), `check_traceability` — **hard refusal** unless the record's `ozolith-v1` identity is checked in as `candidates/<slug>--<hash8>` and that bundle recomputes to the same candidate hash and triple (absent → "promote it first"; tampered/mismatch/legacy → refused; a vendored `results/<hash>/candidate/` copy, when present, is re-verified too); **the candidate is what the tree holds** — `_candidate_dirs_with_hash8` admits real directories only and refuses a symlink under a candidate name (never followed), the wrapper must resolve in place under `candidates/` and its `bundle/` must be a real directory — and `validity_warnings` — **warning** on `leaderboard_valid: false` (reasons: validity note, Resume Leg, unevaluated, classified failure), refusing without `--allow-invalid`; a pending journal under the destination refuses planning. `stage_publication` is a **transaction** (`PublicationTransaction`: `begin` creates the journal `<dest>/.publish-journal.json` exclusively and a private `.publish-staging-<nonce>/`; `stage` re-proves each source through every ancestor immediately before copying it through a no-follow descriptor proven a regular file (`_copy_regular_file`), then re-reads each copy — byte identical to its source and re-proving as the same record; `commit` renames each record dir into place, journaling before and after; `finish` removes staging and journal; `rollback` removes only the directories the journal lists). Any failure rolls back and raises `PublicationRefused`; a failed rollback raises `PublicationRecoveryError` and keeps the journal. `recover_publication(dest)` runs first on the next invocation: completes a transaction that had committed every record, rolls back anything less (including a rename that landed before the journal caught up). **The journal is an untrusted boundary** (`_open_journal` / `_read_journal`: opened `O_NOFOLLOW|O_NONBLOCK`, proven a regular file by `fstat` on the descriptor that is then read; a symlink — dangling or not — a directory, FIFO, socket or device under its name raises `PublicationRecoveryError` from recovery and inspection alike; planning treats any entry at the journal's path as a pending journal). **Recovery is contained** (`Journal.from_dict` + `_removable_directory` / `_validate_staging` / `_validate_record`): the journal must have exactly the written fields, a `staging` name in the generated `.publish-staging-<8 hex>` format, non-empty `planned` names that are plain components (`[A-Za-z0-9][A-Za-z0-9._-]*`, so no separator, `.`/`..`, dot-prefix or absolute path), no repeated name, `committed` ⊆ `planned`, and a `committing` that is planned and not committed; every cleanup target is then proven — before any deletion — a real directory resolving to an immediate child of `dest` (never a symlink) holding only what the transaction copies: under staging, planned record directories each holding a subset of `manifest.json`/`scores.json`; a committed or landed record holding both; every record file a regular file by `lstat`, so a directory (which could hold foreign content `rmtree` would reach), symlink, FIFO, socket or device under a record name is refused. The complete target set is validated before the first removal. A journal failing any check raises `PublicationRecoveryError` with the destination unchanged. `inspect_publication(dest)` is the read-only twin (`RecoveryReport(performed=False)`): `--dry-run` never recovers — a pending journal is reported (`RECOVERY REQUIRED …`) and `main` returns 1 (2 when recovery would fail) with bytes and mtimes untouched. Identical existing records are skipped — only when the destination is a real directory holding both record files as regular files; a symlinked record or record file refuses even with identical bytes — differing ones conflict, and the success summary (`format_committed`) prints only after the commit. `iter_published_records(root)` discovers published runs by manifest only (any depth; dot dirs skipped; `run_id` must equal the directory name; `os.walk` without following links — a symlinked directory or a symlink/special file under a record file's name raises `ResultsRepoError`). Never commits. CLI: `--results-repo` (or `$SILVERQUILLM_RESULTS_REPO`) `--dest published/<subdir> RUN_ID… [--candidates-dir] [--allow-invalid] [--dry-run]`; exit 1 on `REFUSED`, 2 on `RECOVERY FAILED`. |
| `rebuild_results_index.py` | ~60 | **Derived-index regeneration.** Thin CLI over `silverquillm.results_repo.rebuild_index`: rewrites the results repo's `runs.jsonl` purely from the tree (sorted by `(candidate_hash, run_id)`, sorted keys — byte-identical across rebuilds). `--results-repo` or `$SILVERQUILLM_RESULTS_REPO`. A tampered or misplaced record fails the rebuild (exit 1) and leaves the previous `runs.jsonl` unchanged. |
| `mine_promotion_candidates.py` | ~530 | **Discovery-candidate miner.** AST-scans agent-written `tests.py` files in each Validated Results `cards/<card>/` subtree and surfaces behaviors not represented in the canonical audited suite (`benchmarks/<bench>/data/tests/audited/<bench>/<card>/tests.py`). Exposes `mine_candidates(repo_root, *, bench, card, image, run) -> list[Candidate]` and `main()` with `--bench/--card/--image/--run/--format` CLI flags. Loads `discover_validated_runs` from `harvest_validated_results` via `importlib`. **Heuristic**: for each agent test function, extracts a `TestBehavior` (normalized name, docstring, `frozenset` of engine API names via `ast.walk`). A behavior is covered if any audited function matches by (1) normalized name equality or (2) engine-API Jaccard ≥ 0.8 AND ≥1 shared docstring keyword (length > 3). Uncovered behaviors are emitted as `Candidate` dataclass instances; cards with no audited file produce candidates with `note="no audited baseline"`. **Never promotes anything.** Output formats: human-readable `text` (default) or `json`. |
| `check_promotion_candidate.py` | ~530 | **Discovery→promotion bar gate.** Runs three checks on a single candidate test file before a human merges it into the audited suite. **`check_tier(repo_root, bench)`**: reads `benchmarks/<bench>/config.json` and rejects if `tier` is not `beta` or `benchmarking` — fail-closed (missing config/key → reject). **`check_canonical_api(candidate_path, repo_root, bench)`**: AST-scans candidate symbols and rejects if any reference oracle-only engine symbols absent from the canonical engine. `_collect_public_symbols` recurses each engine (`rglob`) and collects module/class/function names **plus** methods, properties, class-body attributes (dataclass fields), and `self`/`cls` instance attributes — so oracle-only primitives that live inside a class (`mana_spent`, `restricted_mana`, `rng`) are caught, not just top-level names. **`check_oracle_gate(candidate_path, card, repo_root, bench)`**: copies oracle `card_impl.py` + candidate into a temp dir, sets PYTHONPATH to oracle workspace engine, runs pytest — fail-closed on subprocess error or timeout. **`check_promotion_candidate(candidate_path, card, repo_root, bench) -> PromotionResult`**: orchestrator; tier check short-circuits on failure (skips remaining expensive checks); returns `PromotionResult(allowed, checks=[CheckResult(name, ok, reason), ...])`. CLI: `python scripts/check_promotion_candidate.py <candidate> --card <card> [--bench sos]`; exits 0 on ALLOWED, 1 on REJECTED. **Never edits, commits, or promotes anything.** |

## Dependencies

- **External**: `requests` (HTTP), Scryfall API
- **Downstream**: `data/replays/card_id_map.json` consumed by `silverquillm/replay/parser.py` and `silverquillm/replay/executor.py`. `cards/stubs/sos_stubs.py` consumed by `tests/audited/sos/conftest.py`. `harvest_validated_results.py` writes to `benchmarks/<bench>/analysis/harvested_results.jsonl` (harvest mode) and `benchmarks/<bench>/analysis/harvested_summary.json` (summary mode).

## Directory Structure

```
scripts/
├── build_card_id_map.py             — Scryfall → card_id_map.json builder
├── generate_audited_stubs.py        — sos.json → sos_stubs.py generator
├── harvest_validated_results.py     — Phase 19 harvest pipeline: discovery + row emission + CLI
├── migrate_validated_results.py     — Legacy validated_results → private results repo backfill (#63)
├── rebuild_results_index.py         — Regenerate the results repo's derived runs.jsonl
├── mine_promotion_candidates.py     — Discovery-candidate miner: AST-scans agent tests vs audited suite
└── check_promotion_candidate.py     — Promotion bar gate: tier + canonical-API + oracle checks; never promotes
```
