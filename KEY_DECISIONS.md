## MSH Task #1 — Player Query / Player Decision protocol

Format: date — decision — why — rejected alternative.

- 2026-06-11 — Exception split `ProtocolError` (engine-fault) vs `IntentError` (test-fault) with the named subclasses. — Locked by prompt; replaces `ScriptExhaustedError` with attributable signals. — One flat exception type (rejected: loses engine-vs-test fault attribution).
- 2026-06-11 — `Answer(selected: tuple[PlayerDecision, ...])`; decline is `Answer(())` legal iff `min==0`. — Locked by prompt; no separate Decline type keeps the surface minimal. — A dedicated `Decline` sentinel (rejected: redundant with empty selection).
- 2026-06-11 — Ordering queries use `min == max == len(options)` with answer order = assignment order. — Locked by prompt; reuses the selection mechanism for damage/trigger ordering. — A separate ordering API (rejected: duplicates the Answer machinery).
- 2026-06-11 — `Intent(pattern: GameRef, preferences: tuple[PlayerDecision,...], postcondition)`; name passed to `start_intent`, not stored on Intent. — Locked by prompt. — Storing name on Intent (rejected: couples identity to the registry key).
- 2026-06-11 — Single Baseline-Intent slot: a regular Intent with empty pattern, consulted only when no card intent matches; at most one active. — Locked by prompt. — A stack of baselines (rejected: ambiguous fallthrough order).
- 2026-06-11 — SUPERSEDED (same day, by the zone-insertion-order entry below): stable option order = sort by `(timestamp, zone_index)` game-state key. — Recorded before Phase 2 implementation on the assumption that timestamp was an existing engine ordering primitive; Phase 2 found cards carry no timestamp attribute, so the implemented canonical order is zone-container insertion order (players by seat index). Only that later entry is canonical.
- 2026-06-11 — Action-vs-choice split: priority-action selection (`stack.py`) and combat declaration of attackers/blockers (`combat.py`) stay action-layer/directive-driven; all other V1 choice sites become Player Queries. — Spec: engine stays imperative, only the choice layer is query-driven ("cast this / activate that" remain directives). — Converting declare-attackers/priority to queries (rejected: the spec reserves proactive turn-based actions for the action channel); spec wins if Phase 2 disproves this.

- 2026-06-11 — Engine elicits choices only through the single `Player.answer(query)` entry point; the action layer (priority, combat declaration) is driven imperatively: priority auto-passes (no legal actions are computed by `_get_legal_actions`), and `declare_attackers_step`/`declare_blockers_step` take the chosen creatures as parameters. — Spec: single `answer` entry point + action layer stays directive-driven; the V1 priority `choose` was already effectively dead (always only "pass"). — Modeling declare/priority as queries (rejected: spec reserves proactive turn-based actions for the directive channel).
- 2026-06-11 — Stable option order is the order objects appear in their zone containers (insertion order, deterministic), players iterated by seat index. — Zone containers are list-backed and ordered; this is a game-state-derived key, never set/dict iteration. — Sorting by a separate timestamp attribute (rejected: cards carry no timestamp; zone insertion order is already stable and deterministic).
- 2026-06-11 — Replay is benchmark-parameterized via a `--benchmark <id>` CLI flag that puts `benchmarks/<id>/workspace` on `sys.path`; `executor._make_replay_player` returns the MSH intent player (with a permissive Baseline Intent) when `engine.intent_player` imports, else the frozen SOS V1 scripted player. — The shared executor must drive either engine without altering the frozen SOS path; the import-fallback factory is engine-agnostic. — A `--benchmark`-keyed `if/else` importing a specific engine (rejected: couples shared code to engine identities; the ImportError fallback is cleaner and keeps SOS byte-for-byte).

- 2026-06-11 — FDN replay parity met (sample_replay.json: 0 divergences on the MSH engine = the V1 baseline). - 2026-06-11 — The yes/no helper is named `query_yes_no`, not `choose_yes_no`. — A helper literally named `choose_yes_no` would trip acceptance-criterion-1's grep for the removed V1 method names; `choose_object`/`choose_mode`/`choose_color` don't collide with the grepped names. — Naming it `choose_yes_no` (rejected: false-positive grep hit indistinguishable from a surviving V1 call).
- 2026-06-11 — fdn_81's V1 `_damage_assignments`/`_resolve_targets` pokes are removed; the planeswalker −4's "8 damage divided as you choose" is re-expressed as NUMBER Player Queries via `choose_number` (one query per target except the last — each remaining target must get ≥1 — with the last target taking the forced remainder; a single target takes all 8 with no query), answered by card intents or the baseline in tests. — "Divided as you choose" is a player choice, and the protocol re-expresses player choices as Player Queries, never as hardcoded engine policy. — Distributing 8 evenly across `chosen_targets` (rejected, reversing the earlier same-day entry: it replaced a player choice with engine behavior; the V1 private poke's exact split was never the thing to preserve — the *choice* was, and a query preserves it).
- 2026-06-11 — The 5 colocated FDN reference tests are kept (they pass against the migrated engine; they test card data/`on_resolve` directly). The canonical intent-style pattern (start_intent/preferences/postcondition + option-set invariant) is shown exemplarily in `test_utils.md`, `engine_tests/test_intent_test_utils.py`, and `engine_tests/test_protocol_targeting.py`. — Those 5 cards' choices (e.g. Bushwhack's modal selection via `chosen_mode`) are not Player-Query-driven, so a full intent-style rewrite would need out-of-scope modal-choice-as-query engine work; acceptance criterion 3 (reference tests green) is met. — Forcing modal choices through queries now (rejected: expands engine scope beyond Task #1's choice-layer conversion).
- 2026-06-11 — Surplus-attr tolerance: smart constructors are strict (unknown attr key → `MalformedAttrsError`, so intents/oracles stay within the blessed vocab); engine-boundary validation (`validate_query`) is lenient on surplus keys but still rejects out-of-domain values on blessed keys. — Spec Extension policy: "attrs closed but surplus-tolerant; engines may attach extra attrs — inert for matching." — Strict-everywhere boundary validation (rejected: would forbid the engine surplus attrs the spec explicitly permits).
- 2026-06-11 — Tests run under `/usr/bin/python3.11` with the committed venv's pure-python site-packages on `PYTHONPATH` (`venv/lib/python3.12/site-packages`). — The committed venv was built for 3.12 but only 3.11 remains on this host; pytest/click are pure-python and import cleanly; engine collects with no syntax errors. — Rebuilding the venv (rejected: no need; would touch environment outside task scope).
- 2026-06-11 — (review fix) `GameRefsRegistry` mints one instance id per *stint*: it tracks each object's last-seen zone and re-mints on every zone arrival, including a return to a previously occupied zone (battlefield → exile → battlefield = three ids). `move_to_zone` calls `refs.note_zone_change(card)` after every move, so continuity breaks even when a stint is never observed by a query (the real fdn_122 flicker path: nothing queries the card in exile); minting stays lazy. — Spec: a zone change yields a new object; a flickered creature must not get its pre-flicker id back — neither via the prior `(id(obj), zone)` cache key, nor via a purely observational last-seen zone that an unobserved stint never updates. — Keying by `(object, zone)` (rejected: conflates pre- and post-flicker objects); observation-only tracking (rejected: the exile leg of a flicker is typically query-silent, so round-trips cache-hit the stale id; pinned by the Kykar end-to-end test in `cards/fdn/fdn_122/tests.py`).
- 2026-06-11 — (review fix) `choose_object` raises `InvalidOptionsError` for empty candidates on a required (`min > 0`, non-optional) choice, and no longer clamps `min` down when it exceeds the option count; declinable empty choices still short-circuit to `None`/`[]`. — Empty-options-with-min>0 is the protocol's engine-fault signal; a card impl with nothing to offer should skip the query, and the helper papering over that hid real card bugs. — Returning `None` for required-but-empty (rejected: silently weakens an impossible query instead of attributing the fault).
- 2026-06-11 — (review fix) All 40 V1-era `except Exception` wrappers in `cards/` are removed: the 37 around `choose_*`/`query_yes_no` calls are deleted outright (an unanswered query now propagates `UnmatchedQueryError`/`ProtocolError` as the spec's hard test-fault, pinned by the fdn_122 `test_unanswered_query_is_a_hard_failure_not_a_token`); fdn_194's wrapper around `query_yes_no` + `cast_spell_free` is deleted too (a failing sanctioned free-cast is an engine fault worth surfacing); fdn_198/fdn_199's wrappers around `mana_pool.pay` become `if not pay(...): return` (pay returns False on insufficient mana, never raises). — Swallowing the IntentError/ProtocolError hierarchy into silent fallbacks ("make a token", "pick the first candidate") defeats fault attribution exactly the way the deleted ScriptExhaustedError fallbacks did. — Keeping the wrappers but narrowing to non-protocol exceptions (rejected: nothing else in these bodies raises; the wrappers were pure V1 migration residue).
- 2026-06-11 — (review fix) A routed *card* intent whose preferences select zero options on a `min > 0` query gets `preference_miss=True` on its transcript `QueryRecord` (the answer is still the first-offered fill); baseline fills and legal declines are never flagged. — A card-intent zero-match usually means a wrong option set or typo'd preference passing silently; audits can assert no record has the flag. — Raising a test-fault error (rejected: the exception hierarchy is locked by the prompt and partial-preference ordering fills are legitimate; a transcript flag catches the smell without a new error type).

## Replay Validation — simulate mode (gameplay simulation)

Format: date — decision — why — rejected alternative.

- 2026-07-02 — `--simulate` CLI flag gates engine-driving replay validation; the default stays the original observer/sync mode and the frozen SOS path is byte-for-byte unchanged (battlefield tapped/PT comparison is also gated on simulate). — The observer mode's reports (and the SOS harness) must stay comparable while the new mode matures. — Making simulation the only behavior (rejected: silently changes SOS validation output and invalidates prior baselines).
- 2026-07-02 — Simulate mode compares state BEFORE resyncing (compare-first-then-resync): divergences are recorded against the state the engine actually reached, then the engine is oracle-corrected to the GRE snapshot so each step validates independently. — The prior sync-before-compare order made zone/life comparison structurally unfalsifiable (0 divergences on 271 games). — Letting divergences cascade without resync (rejected: one miss floods every later step and drowns real signal).
- 2026-07-02 — GRE diffs REPLACE gameObjects (protobuf default-omission: a re-sent object without isTapped is untapped); apply_diff no longer field-merges. — Verified in-corpus: untaps arrive as full object re-sends with the isTapped key absent; sparse merge kept permanents tapped forever, corrupting the reconstructed truth both modes compare against. — Keeping sparse merge with an isTapped special case (rejected: every omitted-default field has the same problem; the schema doc says objects/zones are complete on re-send).
- 2026-07-02 — Shared GRE zones (battlefield/stack/exile, ownerSeatId=0) route per object: battlefield by controllerSeatId, others by ownerSeatId; empty per-seat groups are emitted so excess engine cards get detected. — The zone-owner lookup returned None for seat 0 and silently skipped the three most gameplay-relevant zones (battlefield was never synced, compared, or correlated). — Modeling a shared engine battlefield (rejected: the engine's per-player zone model is settled; routing is a replay-layer concern).
- 2026-07-02 — Seat-2 (opponent) actions also run through the engine in simulate mode: land plays via play_land, casts via cast_spell with hidden-hand shells materialized at reveal time. — Every input the engine needs is public by action time (the cast reveals the card, ManaPaid names the lands, PlayerSubmittedTargets names the targets), and engine-driven seat-2 actions fire the triggers seat-1 validation depends on (e.g. opponent creature dies → Vengeful Bloodwitch). — Pure state-injection for seat 2 (rejected: bypasses move_to_zone so no ETB/dies triggers fire, which surfaced as seat-1 divergences).
- 2026-07-02 — Casting mana comes from ManaPaid annotations by bounded look-ahead keyed to the spell's stack instance id (Arena streams payment annotations AFTER the cast event), deduped by annotation id against the per-snapshot pass; targeting queries are answered by an Intent minted from PlayerSubmittedTargets with engine-instance-id preferences and card-name fallbacks. — This is the Phase-6-specified GRE-derived-intent design, now implementable because the engine actually raises queries during cast_spell. — Free-casting (rejected by user decision: full mana fidelity validates tapping and payment); answering with the permissive baseline only (rejected: first-offered fill ignores the replay's actual targets).
- 2026-07-02 — Combat is driven from GRE object combat state: attackers declared when attackState reaches AttackState_Attacking (Declared precedes the tap by one snapshot), blocks from blockInfo.attackerIds, one engine combat_damage_step per combat, end_combat_step on exit. — attackState/blockState/blockInfo were parsed away by the old field map while 55% of inferred corpus actions were combat the executor skipped outright. — Inferring combat from life/zone deltas (rejected: the typed fields are authoritative and carry blocker ordering).
- 2026-07-02 — play_land invokes land_card.on_resolve(game) before move_to_zone (mirroring _resolve_spell), making on_resolve the enters-tapped/as-enters hook for lands. — Lands never resolve from the stack, so their ETB one-shots (taplands' gain-1-life, Secluded Courtyard's choice) had no invocation point; Secluded Courtyard's docstring already documented this as the expected fix. — A dedicated on_enter hook (rejected: on_resolve is the established convention for ETB one-shots engine-wide).
- 2026-07-02 — The 17 unimportable FDN land stubs (4 basics, 10 gain-life taplands, Evolving Wilds, Rogue's Passage, Soulstone Sanctuary) are implemented; _can_block now consults _cant_be_blocked (set via until-EOT continuous effects). — They are the most-played cards in a limited corpus and their NameError-on-import capped what replay validation could exercise; the _cant_be_blocked flag existed but nothing read it. — Leaving them as MISSING_CARD divergences (rejected by user decision: constant noise on nearly every game).
- 2026-07-02 — cards/loader.py::load_set_registry populates a CardRegistry from cards/<set>/*/card_impl.py (including make_vanilla factory classes, excluding engine bases via module-attribute identity); the replay CLI loads it for any benchmark whose workspace has the loader, and --simulate requires one. — Nothing populated a registry anywhere, so replay validation ran with registry=None and exercised zero card implementations. — A host-side loader in silverquillm/replay (rejected: tests and agent harnesses need the same registry; the workspace owns its card pool).
- 2026-07-03 — Simulate-mode hand arrivals are classified by ObjectIdChanged ORIGIN zone: library or hidden origin → engine draw; visible-zone origin → zone_transition path. Previously ALL provenance arrivals were excluded from draws, and infer_actions can't see them either (the pre-move library object isn't in game_objects) — so every normal turn draw went undriven. — Verified in-corpus: 26 of 47 hand arrivals in a traced game carry library provenance; each undriven draw produced a per-turn hand mismatch. — Keeping the blanket moved_new_ids exclusion (rejected: it was built for bounces, but the normal draw is also a re-mint).
- 2026-07-03 — Hidden-origin plays are synthesized from the ARRIVAL side in simulate mode (executor `_infer_hidden_origin_actions`): a new card on the GRE stack is a spell_cast, a new battlefield land is a land_play, unless an existing action or visible-zone provenance covers it. — infer_actions requires the pre-move object in the previous snapshot, so opponent casts (190/190 sampled) and land plays (311/319) were invisible; the card, its ManaPaid funding, and its PlayerSubmittedTargets are all public at arrival. — Changing shared infer_actions in state.py (rejected: observer mode and the frozen SOS path must stay byte-for-byte; the synthesis is simulate-only, executor-side).
- 2026-07-03 — ManaPaid look-ahead credits the pool but does NOT tap; the tap happens in the per-snapshot pass at the annotation's home snapshot. The look-ahead window is no longer cut when the funded object leaves game_objects (Arena streams payments after fast auto-resolves; instance ids are never reused, so the affected-ids filter is exact). — Early tapping mis-compared the cast snapshot AND the dedup then left the land untapped at the GRE tap moment — a false mismatch pair per cast (~2,700 corpus-wide); the premature window cut starved equip abilities and fast sorceries of funding. — Comparing tapped state leniently (rejected: masks real tap divergence).
- 2026-07-03 — Simulate mode walks the GRE damage-step sequence: combat_damage_step gains a keyword-only sub_step param ('first_strike'/'normal'/None=both, default unchanged); the executor runs one pass per GRE damage step. Turn-structure events fire at GRE boundaries (upkeep/begin-combat/end-step + end-of-turn), and a replay-side cleanup (expire until-EOT effects, clear marked damage & combat flags — no discard, no SBA loop) runs at the turn boundary before untap. — The engine's run_turn is never used by replay, so end-step/upkeep triggers never fired and until-EOT effects never expired; both damage passes at Step_FirstStrikeDamage mis-compared both damage snapshots. — Calling run_turn from replay (rejected: replay follows GRE's structure, not the engine's autonomous loop).
- 2026-07-03 — GRE ability activations drive engine activate_ability when the source has exactly ONE activated ability and no engine-queued trigger matches; mana comes from the same ManaPaid look-ahead (ability instance ids appear in affectedIds), targets from PlayerSubmittedTargets intents. Multi-ability sources are skipped (GRE doesn't say which ability the object is) and reconciled by resync. — activate_ability existed but was never called: taps/effects of Rogue's Passage-style abilities never happened engine-side. — An Arena-ability-grpId→engine-ability mapping table (deferred: needs per-set data; the one-ability case covers most FDN activations).
- 2026-07-03 — Graveyard/exile→stack card arrivals cast via cast_spell_free from the real zone (mana already validated by ManaPaid); multi-blocker damage order is answered by an ordering Intent minted from the observed outcome (blockers that die first were assigned damage first), skipped for same-name attackers (pattern ambiguity) where the baseline first-offered order applies. — Flashback casts previously bare-moved without resolution effects; damage order was first-offered and killed the wrong blocker. — Parsing SelectNResp for the order (rejected: the SelectNReq prompts are stripped from 17lands exports, so bare ids=[0] responses are uninterpretable; outcome inference is exact for the cases that matter).
- 2026-07-03 — _rebuild_instance_map keeps still-valid prior bindings (identity match within the GRE-declared zone group) and only order-matches the remainder; _remove_synced_card also removes the card's continuous effects from effect_manager. — Full order-rematching swapped same-name permanents (basics) every resync, flapping tapped-state comparisons; stale effects from resync-removed permanents kept applying at every apply_all. — (No alternatives worth recording.)
- 2026-07-03 — Replay validation reports are PR artifacts, not repo files: the committed corpus baselines (135k-line replay_simulate_baseline_2026-07-02.json, 6k-line fdn_replay_validation.json) are removed and benchmarks/*/analysis/*.json is gitignored; anchor numbers live in commit messages and the PR body. A REPLAY_INFRA divergence type separates executor-side impossibilities (library empty on a GRE draw, step-event plumbing) from ENGINE_ERROR so that count stays a clean engine/card-bug signal. — Per-divergence dumps were 97% of the PR's line count and grow with every baseline; ENGINE_ERROR was advertised as card-bug signal while containing harness noise. — Keeping a compact summary JSON in-repo (rejected by user decision: all report content lives in the PR).

## Replay Validation — Phase A measurement honesty

Format: date — decision — why — rejected alternative.

- 2026-08-07 — (locked by prompt) Oracle P/T corrections are revocable ContinuousEffects at Layer.POWER_TOUGHNESS/SubLayer.MODIFY_PT with DURATION_PERMANENT, tagged by using the module-level sentinel `_ORACLE_PT_SOURCE` as the effect's `source` (identity-matched via `get_effects_by_source`); the resync's base/modified-stat bake is deleted and corrections are cleared and re-derived from the residual snapshot delta at every resync (never incrementally adjusted). — The bake made temporary GRE-side effects permanent engine-side, producing equal-and-opposite divergence pairs and corrupting every later printed-stat read; clear-all-then-re-derive also drops corrections whose object departed and gives fresh corrections the newest timestamps so they apply after all real effects. — A marker attribute on the effect (rejected: the source-sentinel reuses the existing `get_effects_by_source` query and can never collide with `_remove_synced_card`'s per-card effect cleanup).
- 2026-08-07 — Mid-turn effect re-application is conditional: the resync triggers `apply_all` only when corrections are in play — one reset-then-apply pass to undo prior corrections, one to make fresh corrections live within the same step — and residual deltas are recomputed against the post-reset state whenever a reset ran. — `apply_all`'s reset wipes in-turn state that isn't effect-registered (direct `modified_*` mutations, counters not mirrored to `_base_*`); the fast path keeps the no-correction majority of steps reset-free, and correction steps self-heal numerically because the re-derived correction absorbs any wiped delta. — Unconditional double `apply_all` per resync (rejected: needless reset side effects on every step); undoing prior corrections by subtracting their deltas from card stats (rejected: the resync must never write stats — locked decision).
- 2026-08-07 — The correction's apply callable is battlefield-gated (no-op when its card is off the battlefield). — `apply_all` resets only battlefield objects, so mutating a departed card would leave residue its zone never clears; corrections can outlive their object between a resync and the next turn-boundary cleanup. — Trusting clear-all alone (rejected: `cleanup_mechanical` runs `apply_all` between resyncs).
- 2026-08-07 — (locked by prompt) Simulate-mode MISSING_CARD counts one divergence per (game, missing identity) — identity = mapped card name, else `grpId_<n>` — across three sources: parser-inferred actions, executor-synthesized hidden-origin actions (exposed via `StepResult.synthesized_actions`), and battlefield arrivals of Card/Token objects whose grpId is unmapped or whose name is unregistered; observer mode keeps the original per-occurrence, mapped-actions-only check byte-for-byte. — The old check saw only parser actions with mapped grpIds, so opponent-played unimplemented cards and every token were invisible while repeat plays multiplied the count; dedup per identity makes the number a worklist, not a frequency artifact. — Deduping observer mode too (rejected: observer results must stay comparable to prior baselines); moving the hidden-origin inference before validation (rejected by prompt: exposing the synthesized actions on StepResult keeps the inference where the executor needs it).
- 2026-08-07 — An unmapped grpId that resolves to a registered basic land via GRE subtypes (arbitrary 17lands printings) is identified as that basic, not counted missing — mirroring `_create_card_from_object`, which builds the real registered card for it. — Counting alt-printing Forests as `grpId_<n>` misses would flood MISSING_CARD with cards the engine demonstrably implements, misstating the unimplemented surface in the other direction. — Counting strictly by map membership (rejected: the identity resolution must match what the executor actually instantiates).
- 2026-08-07 — (locked by prompt) Card crashes are per-action failures, never step aborts: the resolution-side `on_resolve` in `_simulate_ability_resolution` is wrapped in the standard per-action try/except → `engine_failures` pattern, and the call-graph audit guarded four more sites — the stack-exit `on_resolve` in `_simulate_zone_transition`, `draw_card` in `_simulate_hand_draws` (draw triggers run card code), the turn-boundary `_replay_cleanup`/`untap_step` (cleanup's `apply_all` runs card effect callables), and the post-compare `_resync_to_snapshot` call site (register_triggers on injected permanents; a resync crash must not discard the step's recorded comparisons — the next resync re-derives from scratch). All new guards re-raise MSH protocol exceptions via MRO-qualname matching (`_is_protocol_exception`) so PROTOCOL_ERROR/QUERY_UNANSWERED keep surfacing per contract. — One bad card was aborting a whole step's measurement and mis-attributing everything downstream. — Guarding `_apply_one_mana_payment` (no card-code path, fixed enum inputs), intent minting (boundary validation IS the protocol contract), and `compare_state` (pure reads, not per-action) — rejected as not card-crash surfaces; widening the ten pre-existing guards to re-raise protocol exceptions (rejected: prompt deems them the correct pattern as-is; noted as a pre-existing nuance).
- 2026-08-07 — (locked by prompt) Dirty-state recovery barrier: a transition is measurable only when it starts from fully restored GRE truth. `_resync_to_snapshot` now returns a bool and sets `_synced` (False on entry, True only on full completion); `execute_step` checks `_synced` at the very top — before `_handle_turn_info`, so an in-step failure (which started clean) is still measured while a carried-over dirty state is not — and on a dirty entry re-runs the resync against the *previous* snapshot. If that recovery completes, the step proceeds normally; if not, `_suppress_unmeasurable` records a REPLAY_INFRA "unmeasurable transition", emits no state comparison, and resyncs forward to the current snapshot so a later step can self-heal. — The old code caught the post-compare resync crash and continued, so the next step compared against partially synchronized state and every mismatch after a resync failure was residue from the earlier failed recovery, not the current transition. — Suppressing only the dirty surface, e.g. P/T, while still comparing zones/life (rejected: partial comparison risks emitting residue; coarse per-transition suppression is the honest floor the prompt mandates — "do not emit state mismatches derived from dirty state"); re-running the identical resync in a retry loop (rejected: re-triggers the same failing card-code path — see the `_effects_broken` latch below).
- 2026-08-07 — Recovery failures are REPLAY_INFRA, not ENGINE_ERROR. The *card* crash that caused the dirtiness is already an ENGINE_ERROR at its own guarded surface; the follow-on "this transition can't be measured" is a replay-harness verdict about measurability, which is exactly what REPLAY_INFRA denotes (kept out of the engine/card-bug signal). — The two facts are distinct — a bad card, and a step we chose not to measure because of it — and conflating them would double-count the card against ENGINE_ERROR. — Recording the suppression as a second ENGINE_ERROR (rejected: inflates the card-bug worklist with a harness decision).
